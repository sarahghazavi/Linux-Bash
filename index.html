لینوکس و بش

لینوکس و شل

لینوکس متن‌باز است و معمولا سریع‌تر از یک سیستم بسته راه‌اندازی می‌شود. ترمینال پنجره‌ای است که حرف می‌زنی. شل برنامه‌ای است که آن حرف را می‌فهمد و به کرنل می‌سپارد. بش یعنی Bourne-Again Shell. zsh همان خانواده است با تکمیل بهتر. پاورشل مال ویندوز است.

اگر خط فرمان با $ تمام شود کاربر عادی هستی. اگر با # تمام شود root هستی.

پکیج

dpkg -i file.deb یک بستهٔ دانلودشده را نصب می‌کند و وابستگی را خودش نمی‌آورد. apt مخزن را می‌گردد و وابستگی را هم می‌کشد.

sudo apt update
sudo apt install curl jq
sudo apt --fix-broken install
apt list --installed
apt show curl
sudo apt remove curl          # برنامه می‌رود، تنظیمات می‌ماند
sudo apt purge curl           # تنظیمات هم می‌رود
sudo apt upgrade
sudo apt full-upgrade

snap install name برای برنامه‌هایی است که در مخزن apt نیستند. pip install -r requirements.txt پکیج پایتون را از روی فایل نیازمندی نصب می‌کند. روی سیستم از pip3 استفاده کن، نه اینکه پکیج سیستم را با pip قاطی کنی.

پروسس و سیگنال

پروسس یک اجرای زنده از برنامه است. دیمون پروسسی است که در پس‌زمینه می‌ماند؛ اسم خیلی‌هایشان به d ختم می‌شود، مثل sshd.

دستور کار
ps aux a همهٔ ترمینال‌ها، u کاربر، x حتی بدون ترمینال
ps -u name فقط پروسس‌های یک کاربر
ps -ef فرمت دیگر، با ستون PPID
pstree درخت. systemd معمولاً pid برابر ۱ است
pgrep -a nginx pid از روی اسم. -a خط فرمان را هم نشان می‌دهد
top / htop مصرف زنده. در top با q بیا بیرون
jobs کارهای همین شل
bg %1 / fg %1 پس‌زمینه و پیش‌زمینه
cmd & از اول در پس‌زمینه

Ctrl+C سیگنال INT می‌فرستد. Ctrl+Z توقف (STOP) است، مرگ نیست. بعد با fg یا bg برش می‌گردانی.

شماره اسم معنی
1 SIGHUP ترمینال بسته شد؛ بعضی سرویس‌ها با این reload می‌شوند
2 SIGINT Ctrl+C
3 SIGQUIT خروج همراه core dump
9 SIGKILL کشتن اجباری. برنامه فرصت تمیزکاری ندارد
15 SIGTERM درخواست معمولی بستن. پیش‌فرض kill
18 SIGCONT ادامه بعد از توقف
19 SIGSTOP توقف اجباری
20 SIGTSTP Ctrl+Z 
kill 1234            # SIGTERM
kill -9 1234         # SIGKILL
kill -l              # لیست سیگنال‌ها
ping -c 3 1.1.1.1    # سه بسته، بعد تمام
ping -q -c 2 -W 1 example.com

grep یعنی global regular expression print: خط‌هایی را که الگو دارند جدا می‌کند.

ps aux | grep nginx
grep -n "error" /var/log/syslog     # شمارهٔ خط
grep -Rni "TODO" .                  # بازگشتی، شماره، بدون حساسیت به حروف
grep -v "^#" config | grep -v "^$"  # خط‌های کامنت و خالی را حذف کن

systemd

موقع بوت، کرنل systemd را صدا می‌زند. systemd فایل‌سیستم را سوار می‌کند و سرویس‌ها را بالا می‌آورد. هر چیزی که کنترل می‌کند یک unit است: service، socket، timer، mount، target، device. 

systemctl start nginx
systemctl stop nginx
systemctl status nginx
systemctl restart nginx          # می‌کشد و دوباره شروع می‌کند
systemctl reload nginx           # تنظیم تازه، اگر خود سرویس بلد باشد
systemctl reload-or-restart nginx
systemctl enable nginx           # با بوت بیاید بالا
systemctl disable nginx
systemctl is-active nginx
systemctl is-enabled nginx
systemctl list-units
systemctl list-units -t service
systemctl list-unit-files        # حتی unitهایی که لود نشده‌اند
journalctl -u nginx -e           # لاگ همان سرویس، برو آخر فایل
journalctl -xe                   # خطاهای اخیر کل سیستم
journalctl -u nginx --since "1 hour ago"

شروع اسکریپت

#!/usr/bin/env bash
set -euo pipefail
# -e  با اولین خطا خارج شو
# -u  متغیر تعریف‌نشده خطا است
# -o pipefail  خطای وسط پایپ گم نشود

chmod +x script.sh
./script.sh

exit 0 یعنی موفق. هر عدد غیر صفر یعنی شکست. exit 1 قرارداد معمول خطای عمومی است.

چهار روش اجرا

دستور چه می‌شود
./script.sh باید chmod +x داشته باشد. خط shebang تعیین می‌کند کدام مفسر اجرایش کند
bash script.sh chmod لازم نیست و shebang نادیده گرفته می‌شود. داور سؤال‌های المپیک همین‌طور اجرا می‌کند
sh script.sh با sh اجرا می‌شود که روی اوبونتو dash است، نه بش
source script.sh یا . script.sh داخل همین شل اجرا می‌شود؛ متغیرها و تابع‌هایش بعد از تمام شدن هم می‌مانند. exit در آن خود ترمینال را می‌بندد

خط اول می‌تواند #!/bin/bash باشد یا #!/usr/bin/env bash که بش را از PATH پیدا می‌کند. مسیر بش را با which bash ببین. اگر خط اول #!/bin/sh باشد فقط POSIX مجاز است: آرایه، [[ ]]، ${var,,}، &> و <<< کار نمی‌کنند.

فایل از ویندوز با CRLF آمده علامت‌ها: bad interpreter: /bin/bash^M یا $'\r': command not found. درمان: sed -i 's/\r$//' script.sh یا dos2unix script.sh. برای جلوگیری، در ویرایشگر پایان خط را LF بگذار و در ریپو فایل .gitattributes با خط * text=auto eol=lf داشته باش.
ابزارهای کمکی shellcheck script.sh اشتباه کوت و شرط را قبل از اجرا پیدا می‌کند (sudo apt install shellcheck). bash -n script.sh فقط سینتکس را چک می‌کند و چیزی اجرا نمی‌کند. bash -x script.sh هر دستور را با یک + اول خط چاپ می‌کند تا ببینی کجا خراب می‌شود. در WSL پروژه را داخل خانهٔ لینوکس (~) نگه دار، نه /mnt/c؛ آنجا کندتر است و دسترسی فایل‌ها عجیب می‌شود. تله‌های set -e در بخش کد خروج آمده است.

متغیرها

فاصله دور = مقدار را خراب می‌کند name = "sara" یعنی دستور name را با دو آرگومان اجرا کن. درستش name="sara" است. 
name="sara"
echo "$name"
echo "${name}_notes"     # اگر بچسبانی به حرف، آکولاد لازم است

read -r city                          # یک خط، بدون تفسیر \
read -r -p "شهر: " city               # پیام می‌دهد و در city ذخیره می‌کند
echo "سلام $city"

# REPLY فقط وقتی پر می‌شود که اسم متغیر ندهی
read -r -p "ادامه؟ "
echo "$REPLY"
read -p ذخیره می‌کند اگر بعد از پیام اسم متغیر باشد، مقدار آنجاست. -r یعنی بک‌اسلش را معمولی بخوان، نه اینکه ورودی خام نباشد.
read با دلار نمی‌خواهد درست: read name. اگر بنویسی read $name، شل اول $name را باز می‌کند. وقتی خالی است، دستور read بی‌اسم اجرا می‌شود، جواب در REPLY می‌رود و name همچنان خالی می‌ماند.

آرگومان‌های اسکریپت

./script.sh "DevOps notes" extra
# $0 = خود اسکریپت
# $1 = DevOps notes
# $2 = extra
# $# = تعداد آرگومان
# $@ = همه، جدا جدا
# $* = همه، چسبیده با IFS

title="${*:2}"    # از آرگومان دوم تا آخر، یک رشته
rest="${@:2}"     # همان، ولی برای پاس دادن دوباره بهتر است
${*:2} تکهٔ یک رشته نیست این از پارامترهای مکانی است. اگر اسکریپت را این‌طور صدا بزنی: ./script.sh save "my title here" آن‌وقت $1 برابر save است و title="${*:2}" می‌شود my title here. برای بریدن خود یک متغیر بخش رشته‌ها را ببین. 
name="$1"
shift             # $2 می‌آید جای $1، و بقیه یکی جلو می‌آیند
echo "باقی: $#"

قبل از کار با $1 تعداد آرگومان را چک کن. پیام استفاده روی stderr برود و اسکریپت با کد غیر صفر خارج شود. $0 اسم خود اسکریپت است، پس پیام با هر اسمی درست می‌ماند.

if [ "$#" -lt 2 ]; then
  echo "usage: $0 <src> <dst>" >&2
  exit 1
fi

چهار شکل مقدار پیش‌فرض، وقتی متغیر خالی یا تعریف‌نشده است:

echo "${port:-8080}"     # اگر خالی بود 8080 نشان بده، port عوض نمی‌شود
echo "${port:=8080}"     # اگر خالی بود ست کن و نشان بده
echo "${port:?لازم است}"  # اگر خالی بود خطا و خروج

کوت و شکستن کلمه

بش بعد از باز کردن متغیرها، نتیجه را از روی فاصله، تب و خط جدید به کلمه می‌شکند (word splitting) و بعد * و ? را به اسم فایل‌ها باز می‌کند (globbing). کوت همین دو کار را کنترل می‌کند.

شکل رفتار
$x باز می‌شود، می‌شکند و glob هم می‌شود. خطرناک است
"$x" متغیر و $(...) باز می‌شوند ولی نتیجه یک کلمه می‌ماند
'$x' هیچ‌چیز باز نمی‌شود؛ متن خام
$'a\tb' نویسه‌های ویژه مثل تب و خط جدید را می‌فهمد 
f="my notes.txt"
touch $f            # دو فایل می‌سازد: my و notes.txt
touch "$f"          # یک فایل: my notes.txt

x=""
[ $x = sara ]       # خطا: unary operator expected (می‌شود [ = sara ])
[ "$x" = sara ]     # درست

set -- "a b" c      # دو آرگومان
for v in $@; do echo "<$v>"; done      # <a> <b> <c>   غلط
for v in "$@"; do echo "<$v>"; done    # <a b> <c>   درست
قاعدهٔ طلایی هر $var و $(cmd) را دابل‌کوت کن، مگر اینکه عمداً شکستن کلمه بخواهی. برای آرگومان‌ها "$@" بنویس، نه $@. داخل [[ ]] و سمت راست var=$other شکستن کلمه نیست و کوت لازم نیست، ولی کوت کردن ضرری ندارد.
ShellCheck همین را می‌گیرد هشدار SC2086 یعنی «متغیر بی‌کوت». اگر ShellCheck را نصب کرده‌ای، قبل از تحویل هر اسکریپت یک‌بار اجرایش کن.

خروجی، خطا و redirect

هر برنامه سه جریان دارد. پیش‌فرض ورودی کیبورد است و هر دو خروجی ترمینال. redirect یعنی عوض کردن مقصد هرکدام.

شماره اسم پیش‌فرض عملگر
0 stdin کیبورد <
1 stdout ترمینال > یا 1>
2 stderr ترمینال 2>
عملگر کار
cmd > f stdout را در فایل می‌ریزد. فایل را می‌سازد یا از نو می‌نویسد
cmd >> f به ته فایل اضافه می‌کند
cmd 2> f / 2>> فقط خطا را در فایل می‌ریزد / به ته اضافه می‌کند
cmd &> f / &>> stdout و stderr هر دو در فایل. فقط بش؛ در sh از > f 2>&1 استفاده کن
cmd 2>&1 خطا را به همان جایی می‌فرستد که stdout الان اشاره می‌کند
echo msg >&2 خروجی این دستور را روی stderr می‌فرستد؛ برای پیام خطا در اسکریپت
cmd < f ورودی را از فایل می‌دهد، نه از کیبورد
cmd1 | cmd2 stdout اولی ورودی دومی می‌شود. خطا رد نمی‌شود
cmd | tee f هم روی صفحه نشان می‌دهد و هم در فایل می‌ریزد
cmd 2> /dev/null خطا را دور می‌ریزد. با > /dev/null 2>&1 هر دو را 
echo "hi" > out.txt
ls nope 2> err.txt                 # فقط خطا
ls nope . > all.txt 2>&1            # هر دو در all.txt
ls nope 2>&1 > all.txt            # غلط: خطا هنوز روی ترمینال می‌آید
echo "فایل نیست" >&2               # پیام خطا روی stderr
ترتیب redirect مهم است redirectها از چپ به راست اعمال می‌شوند. 2>&1 یعنی «خطا را به جایی بفرست که stdout همین الان هست». در > f 2>&1 اول stdout به فایل می‌رود و بعد خطا هم همان‌جا. در 2>&1 > f خطا به ترمینال بسته می‌شود و بعد stdout عوض می‌شود.
فایل ورودی را با خروجی نریز sort f > f قبل از اجرای sort فایل f را خالی می‌کند. خروجی را در فایل دیگری بریز، یا از sort -o f f استفاده کن.
در سؤال‌های کوئرا فقط stdout سنجیده می‌شود هر پیام دیباگ یا خطا را روی stderr بفرست (>&2)، وگرنه خروجی اشتباه حساب می‌شود.

کد خروج و $?

هر دستور وقتی تمام می‌شود یک عدد از ۰ تا ۲۵۵ برمی‌گرداند. صفر یعنی موفق و هر عدد دیگر یعنی شکست. این عدد در $? است، ولی با اجرای دستور بعدی عوض می‌شود.

کد معنی
0 موفق
1 خطای عمومی. در grep یعنی «پیدا نشد»
2 استفادهٔ غلط از دستور. در grep یعنی خطا، مثلاً فایل نیست
126 فایل هست ولی اجرایی نیست
127 دستور پیدا نشد
128+n با سیگنال n کشته شده: ۱۳۰ = Ctrl+C، ۱۳۷ = SIGKILL، ۱۴۳ = SIGTERM

if خود دستور را اجرا می‌کند

if grep -q "^root:" /etc/passwd; then echo "هست"; fi
if ! ping -c 1 -W 1 example.com > /dev/null; then echo "down" >&2; fi

mkdir out && cd out          # فقط اگر mkdir موفق بود
cmd || echo "failed" >&2       # فقط اگر cmd شکست خورد
cmd1 ; cmd2                     # هر دو، بی‌توجه به نتیجه

[ ] و [[ ]] هم فقط کد خروج می‌دهند. برای همین لازم نیست [ $? -eq 0 ] بنویسی؛ خود دستور را بده به if.

$? را فوراً ذخیره کن

grep -q "x" file
rc=$?                          # قبل از هر دستور دیگر
if [ "$rc" -eq 0 ]; then echo "پیدا شد"; fi

false; echo "$?"               # 1
false; [ 1 = 1 ]; echo "$?"    # 0   دستور [ ] مقدار را عوض کرد

exit در برابر return

exit n کل اسکریپت را می‌بندد. return n فقط از تابع (یا از فایلی که با source اجرا شده) بیرون می‌آید و کد خروج همان تابع می‌شود. بدون عدد، کد آخرین دستور برگردانده می‌شود. عددها بین ۰ تا ۲۵۵اند و ۲۵۶ می‌شود ۰. با return نمی‌شود داده برگرداند، فقط وضعیت.

is_boss(){
  [[ "${1,,}" == herbert ]]      # کد خروج همین شرط، کد خروج تابع می‌شود
}
if is_boss "$user"; then echo "خوش آمدی"; else echo "ناشناس" >&2; fi
تله‌های set -e
  • ((i++)) وقتی i صفر است کد ۱ می‌دهد و اسکریپت می‌میرد. i=$((i + 1)) بنویس.
  • read وقتی به آخر فایلِ بدون \n برسد شکست می‌خورد، ولی متغیر را پر می‌کند. زیر set -e اسکریپت همان‌جا می‌میرد. راهش read -r x || [[ -n $x ]] است.
  • local x=$(cmd) کد خروج cmd را قورت می‌دهد، چون کد خروج local صفر است. اول local x و بعد x=$(cmd) بنویس.
  • شکست وسط پایپ دیده نمی‌شود، مگر set -o pipefail داشته باشی.
  • دستورِ داخل شرط if یا قبل از && و || باعث مردن اسکریپت نمی‌شود.

خواندن فایل در اسکریپت

ورودی سؤال‌های کوئرا معمولاً یک فایل در پوشهٔ کاری است، نه stdin. اسکریپت باید خودش آن را باز کند؛ وگرنه روی stdin منتظر می‌ماند و تا ابد می‌ایستد. قالب امن برای خواندن خط‌به‌خط:

while IFS= read -r line || [[ -n $line ]]; do
  [[ -z ${line//[[:space:]]/} ]] && continue   # خط خالی
  read -r id gate badge event <<< "$line"        # شکستن به ستون
  echo "$id $event"
done < gate-log.txt
تکه چرا لازم است
IFS= فاصله‌های اول و آخر خط را نمی‌خورد
-r بک‌اسلش را معمولی می‌خواند
|| [[ -n $line ]] اگر خط آخر \n نداشته باشد، read شکست می‌خورد ولی متغیر پر است. بدون این تکه آخرین خط گم می‌شود
${line//[[:space:]]/} همهٔ فاصله‌ها و تب‌ها را برمی‌دارد تا خطِ فقط‌فاصله هم خالی حساب شود
read -r a b c <<< "$line" خط را از روی هر تعداد فاصله می‌شکند. اگر ستون کم باشد، باقی متغیرها خالی‌اند و اگر زیاد باشد، آخرین متغیر بقیه را می‌گیرد
خط آخر بدون \n فایلی که با printf 'IRAN' > f ساخته شود \n آخر ندارد. اگر || [[ -n $line ]] را ننویسی، حلقه برای آخرین خط اجرا نمی‌شود. زیر set -e خودِ read هم اسکریپت را می‌کشد. 
IFS= read -r code < team.txt || [[ -n $code ]]    # فایل یک‌خطی، با \n آخر یا بی‌آن
printf 'hello %s\n' "$code"

تابع و local

تابع باید قبل از اولین صدا زدنش تعریف شده باشد. صدا زدنش مثل یک دستور است: بدون پرانتز و با آرگومان‌هایی که با فاصله جدا می‌شوند. داخل تابع $1، $2 و $# مال خود تابع‌اند، نه اسکریپت؛ فقط $0 همان اسم اسکریپت می‌ماند.

showname(){
  local name="$1"
  echo "Hello $name"
}
showname Herbert              # Hello Herbert
msg=$(showname Sara)          # خروجی تابع داخل متغیر

showuptime(){
  local up since
  up=$(uptime -p | cut -c4-)
  since=$(uptime -s)
  printf 'up for %s, since %s\n' "$up" "$since"
}
showuptime

forward(){ other_cmd "$@"; }  # آرگومان‌ها را دست‌نخورده پاس بده
متغیر تابع به‌طور پیش‌فرض سراسری است اگر داخل تابع up=5 بنویسی، بعد از تابع هم $up برابر ۵ است و می‌تواند متغیر هم‌نامِ اسکریپت را خراب کند. local up=5 آن را به تابع محدود می‌کند. local فقط داخل تابع معنی دارد.
local x=$(cmd) شکست را پنهان می‌کند کد خروج local صفر است و جای کد cmd را می‌گیرد، پس set -e و $? شکست را نمی‌بینند. اول local x و بعد x=$(cmd) بنویس. ShellCheck این را SC2155 می‌نامد.
تابع داده برنمی‌گرداند، فقط وضعیت return n یک عدد ۰ تا ۲۵۵ است و کد خروج تابع می‌شود. برای برگرداندن متن، آن را با echo یا printf چاپ کن و بیرون با $(f) بگیر. پیام خطا را روی stderr بفرست تا وارد مقدار گرفته‌شده نشود. تفاوت return و exit در بخش کد خروج است.

sed -n '20p' file
awk 'NR == 20' file
# بازه
sed -n '15,20p' file
awk 'NR >= 15 && NR <= 20' file

sort

sed

جریان متن را خط‌به‌خط عوض می‌کند. s یعنی substitute. جداکننده لزوماً اسلش نیست؛ وقتی با مسیر کار داری # خواناتر است.

sed 's/foo/bar/' file            # اولین foo در هر خط
sed 's/foo/bar/g' file           # همه
sed -n 's/foo/bar/p' file        # فقط خط‌هایی که عوض شدند
sed -n '5p' file                 # خط ۵
sed -n '5,10p' file
sed '5,10d' file                 # این خط‌ها را حذف کن
sed '/^#/d' file                 # خط‌های کامنت
sed '/error/!d' file             # فقط خط‌های error بماند

name=$(printf "%s" "$name" | sed 's/|//g')
name=$(printf "%s" "$name" | sed 's/^"*//; s/"*$//')
name=$(printf "%s" "$name" | sed "s#|$url\$##")

^"*" یعنی ابتدای خط و هر تعداد دابل‌کوت. "*$ یعنی دابل‌کوت‌های انتهای خط. |$url$ یعنی یک پایپ و خود url دقیقاً در انتهای خط.

sed -i روی مک و لینوکس یکی نیست لینوکس: sed -i 's/a/b/g' file. مک: sed -i '' 's/a/b/g' file. برای جزوه، خروجی را در فایل تازه بریز تا غافلگیر نشوی: sed 's/a/b/g' file > file.new
نسخهٔ پشتیبان با -i.bak sed -i.bak 's/a/b/g' file فایل را عوض می‌کند و نسخهٔ قبلی را در file.bak نگه می‌دارد. پسوند باید به -i بچسبد؛ این شکل روی گنو و مک هر دو کار می‌کند. اگر متغیر شل را داخل الگو می‌گذاری از دابل‌کوت استفاده کن: sed "s/$old/$new/g" file. ولی اگر مقدار متغیر / یا & داشته باشد، دستور خراب می‌شود.

awk

هر خط را به ستون می‌شکند. $1 ستون اول است، $NF ستون آخر، NF تعداد ستون، NR شمارهٔ خط.

awk '{ print $1 }' file
awk -F'|' '{ print $NF }' file          # جداکننده پایپ، ستون آخر
awk -F: '{ print $1, $3 }' /etc/passwd  # اسم و uid
awk -F: '$3 >= 1000 { print $1 }' /etc/passwd
awk 'NR == 5' file
awk 'NR > 1 { print }' file             # بدون هدر
awk '{ sum += $1 } END { print sum }' numbers.txt

در مثال بوکمارک، url ستون آخر است:

url=$(printf "%s" "$line" | awk -F'|' '{ print $NF }')

متغیر شل داخل awk

n=3
awk -v n="$n" 'NR == n' file                        # خط n‌ام
tr '\n' ' ' < file | awk -v n="$n" '{ print $n }'    # کلمهٔ n‌ام کل فایل
hostname -I | awk '{ print $1 }'                    # اولین آدرس IP

شل داخل تک‌کوتِ awk چیزی باز نمی‌کند، پس مقدار را با -v به awk می‌دهی. awk هر خط را یک ردیف می‌بیند؛ برای «کلمهٔ n‌ام فایل» اول با tr خط‌ها را به فاصله تبدیل می‌کنیم تا کل فایل یک خط شود.

رجکس عملی

یک خط مثل "نام"|https://example.com را به اسم و آدرس بشکن. جداکننده | است و آدرس آخرین ستون است، چون خود اسم هم ممکن است پایپ داشته باشد.

line='"Linux | notes"|https://example.com/a'

url=$(printf "%s\n" "$line" | awk -F'|' '{ print $NF }')
name=$(printf "%s\n" "$line" | sed "s#|$url\$##")
name=$(printf "%s\n" "$name" | sed 's/|//g')
name=$(printf "%s\n" "$name" | sed 's/^"*//; s/"*$//')
printf "| %s | %s |\n" "$name" "$url" >> unique_bookmarks.md

قدم‌ها: آخر خط را به‌عنوان url بردار، همان url را از ته خط بکن، پایپ‌های باقی‌ماندهٔ داخل اسم را بردار، کوت‌های دور اسم را بردار، یک ردیف مارک‌داون بنویس.

تکه معنی
^ / $ ابتدا / انتهای خط
. هر نویسه
* صفر یا بیشتر از عبارت قبلی
"* صفر یا بیشتر دابل‌کوت
\ نویسهٔ بعدی معمولی است. \$ یعنی خود علامت دلار، نه انتهای خط، وقتی داخل دابل‌کوت بش است
# در sed جداکنندهٔ دستور s، تا لازم نباشد اسلش‌های url را فرار بدهی

همان کار با پارامترهای بش، اگر پایپ فقط یک بار جداکننده باشد:

url="${line##*|}"
name="${line%|$url}"
name="${name//|/}"
name="${name#\"}"
name="${name%\"}"

curl

client URL. صفحه، API، هدر، و آپلود را از ترمینال می‌گیرد. wget بیشتر برای دانلود فایل است.

فلگ کار
-s / -S ساکت / اگر ساکت است باز هم خطا را نشان بده. معمولاً با هم: -sS
-f اگر HTTP خطا بود (۴۰۴، ۵۰۰) خود curl هم شکست بخورد
-L ریدایرکت را دنبال کن
-o file / -O ذخیره با اسم دلخواه / با اسم خود URL
-I فقط هدر، درخواست HEAD
-i هدر به‌علاوهٔ بدنه
-v درخواست و پاسخ، برای دیباگ
-X METHOD GET POST PUT DELETE. با -d خودش POST می‌شود
-H "K: V" هدر
-d 'a=1' بدنه
-u user:pass Basic auth
-k گواهی TLS را چک نکن. فقط برای تست لوکال
-w '%{http_code}' بعد از پاسخ، مثلاً کد وضعیت
-m 10 مهلت به ثانیه

curl -I https://example.com
curl -sS -H "Accept: application/json" https://api.example.com/items
curl -sS -X POST -H "Content-Type: application/json" \
  -d '{"city":"tehran"}' https://api.example.com/weather
code=$(curl -sS -o /dev/null -w "%{http_code}" https://example.com)
echo "$code"

python3 -m http.server 8080

jq

فیلتر JSON. بدون jq باید با sed روی آکولاد ببُری و می‌شکند.

curl -fsSL https://example.com/data.json | jq .
jq '.name' data.json
jq -r '.name' data.json          # -r رشتهٔ خام، بدون کوت اضافه
jq '.items[0].url' data.json
jq '.items[].name' data.json
jq -r '.[] | "\(.name) \(.url)"' data.json
jq 'map(select(.ok == true))' data.json

name=$(curl -fsSL "$url" | jq -r '.title')
echo "$name"

اگر مقدار null باشد و -e بگذاری، jq با وضعیت غیر صفر خارج می‌شود و زیر set -e اسکریپت می‌ایستد.

eval

eval یک رشته را دوباره به‌عنوان دستور اجرا می‌کند. برای ساختن دستور پویا وسوسه‌کننده است و اگر ذره‌ای از آن رشته از کاربر، فایل، یا اینترنت آمده باشد، همان رشته دستور می‌شود.

# بد: هر چه داخل cmd باشد اجرا می‌شود
cmd="rm -rf /"
# eval "$cmd"

# شکل امن برای دستورهای خودت: آرایه
cmd=(ls -la "/tmp/my notes")
"${cmd[@]}"

# شکل امن برای مقدار
printf -v greeting "سلام %s" "$name"
echo "$greeting"
کی eval قابل دفاع است فقط روی رشته‌ای که خودت ساخته‌ای و هیچ ورودی خارجی داخلش نیست. حتی آن‌وقت هم آرایهٔ دستور معمولاً همان کار را می‌کند. خروجی declare -p را گاهی با eval برمی‌گردانند، چون خودش سینتکس بش است؛ باز هم منبعش باید مطمئن باشد.

فیلم انگلیسی Bash Scripting Tutorial for Beginners

فیلم Bash Scripting Tutorial for Beginners از کانال freeCodeCamp است و مدرسش Herbert از Herbertech است. کد فیلم در ریپوی خود مدرس هست. این بخش نکتهٔ هر فصل را کنار جای آن در جزوه می‌گذارد.

فصل فیلم نکتهٔ اصلی در جزوه
مقدمه بش یعنی Bourne Again Shell؛ همه‌جا هست و سبک است. برای کار سنگین (شیءگرایی، ساختار داده، منطق پیچیده) پایتون بهتر است و ابزارهایی مثل Ansible بعضی کارها را جایگزین کرده‌اند لینوکس و شل
اولین اسکریپت shebang، کامنت با #، اجرای دستورها خط‌به‌خط از بالا، و اسم متغیر که حساس به حروف است و فقط حرف، رقم و _ دارد شروع اسکریپت، متغیرها
پارامتر موقعیتی $0 اسم اسکریپت، $1 تا $n، و چک کردن $# قبل از استفاده متغیرها
redirect > >> 2> 2>> &> < << و | خروجی، خطا و redirect
test operators، if/elif/else عددی، رشته‌ای، فایلی و منطقی؛ -z و -n؛ -nt و -ot شرط و مقایسه
case وقتی چند مقدار را می‌سنجی از if/elif خواناتر است. a | b) برای «یا» و *) برای بقیه شرط و مقایسه
آرایه‌ها arr=(…)، ${arr[i]}، ${arr[@]}، declare -a، arr[i]=x، arr+=(…) آرایه‌ها
تابع تعریف و صدا زدن، آرگومان تابع، و متغیر سراسری در برابر local تابع و local
exit code return 0 و return 1 در تابع و چک کردن با $? کد خروج
AWK و SED در پروژهٔ Jarvis از sed -i.backup و از tr همراه awk -v استفاده شده sed، awk

دو پروژهٔ فیلم

  • منوی انتخاب: cat << EOF برای چاپ منو، read برای گرفتن گزینه و case برای اجرا. مثالش در بخش شرط و مقایسه است.
  • Jarvis: اسکریپت مدیریتی با آرگومان‌های help، ip، hostname، uptime، datetime، replacewords، readelement و countdown. هر کدام یک تابع است و case "$1" صدایشان می‌زند. replacewords با sed -i.backup کار می‌کند، readelement با tr و awk -v، countdown با seq و sleep، و آخر اسکریپت هر اجرا با >> در یک فایل لاگ نوشته می‌شود.
اشتباه‌هایی در کد فیلم که نباید کپی کنی
  • [ ${1,,} = herbert ] بی‌کوت است. اگر آرگومان خالی باشد خطای unary operator expected می‌دهد. درست: [ "${1,,}" = herbert ] یا [[ ${1,,} == herbert ]].
  • read $NAME در منوی فیلم غلط است و باید read NAME باشد. نتیجهٔ غلط: Hello بدون اسم.
  • echo Hello $FIRST_NAME $LAST_NAME و ls $path بی‌کوت‌اند و اگر مقدار فاصله داشته باشد می‌شکنند.
  • README فیلم می‌گوید آرایه را می‌شود با () یا [] یا {} ساخت. فقط پرانتز درست است.
  • -a و -o داخل [ ] منسوخ و مبهم‌اند. دو [ ] با && و || یا [[ ]] بنویس.
  • تابع‌های فیلم local up=$(uptime -p ...) دارند که کد خروج را قورت می‌دهد. اعلام و مقداردهی را جدا کن.
  • $? باید بلافاصله بعد از تابع خوانده شود. اگر یک echo وسط بیفتد، مقدارش عوض می‌شود.
جزوهٔ شخصی لینوکس و بش. دستورها را روی ماشین خودت امتحان کن؛ فلگ -i در sed بین گنو و مک فرق دارد.
