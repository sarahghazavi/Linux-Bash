لینوکس و بش

لینوکس و شل

لینوکس متن‌باز است و معمولا سریع‌تر از یک سیستم بسته راه‌اندازی می‌شود. ترمینال پنجره‌ای است که حرف می‌زنی. شل برنامه‌ای است که آن حرف را می‌فهمد و به کرنل می‌سپارد. بش یعنی Bourne-Again Shell. zsh همان خانواده است با تکمیل بهتر. پاورشل مال ویندوز است.

اگر خط فرمان با $ تمام شود کاربر عادی هستی. اگر با # تمام شود root هستی.

/bin و /usr/bin دستورهای معمولی
/sbin و /usr/sbin دستورهای مدیریتی
/etc تنظیمات، از جمله کاربران و گروه‌ها
/home خانهٔ کاربران
/var لاگ و داده‌ای که عوض می‌شود
/tmp فایل موقت
man cmdراهنمای کامل
cmd --helpخلاصهٔ فلگ‌ها
apropos keywordجستجو در راهنماها؛ وقتی اسم دستور را نمی‌دانی
which cmdکدام فایل اجرا می‌شود
type cmdدستور است، alias است، یا تابع

پکیج

dpkg -i file.deb یک بستهٔ دانلودشده را نصب می‌کند و وابستگی را خودش نمی‌آورد. apt مخزن را می‌گردد و وابستگی را هم می‌کشد.

sudo apt update
sudo apt install curl jq
sudo apt --fix-broken install
apt list --installed
apt show curl
sudo apt remove curl          # برنامه می‌رود، تنظیمات می‌ماند

sudo apt upgrade
sudo apt full-upgrade

snap install name برای برنامه‌هایی است که در مخزن apt نیستند. pip install -r requirements.txt پکیج پایتون را از روی فایل نیازمندی نصب می‌کند. روی سیستم از pip3 استفاده کن، نه اینکه پکیج سیستم را با pip قاطی کنی.

پروسس و سیگنال

پروسس یک اجرای زنده از برنامه است. دیمون پروسسی است که در پس‌زمینه می‌ماند؛ اسم خیلی‌هایشان به d ختم می‌شود، مثل sshd.

دستور کار
ps aux a همهٔ ترمینال‌ها، u کاربر، x حتی بدون ترمینال
ps -u name فقط پروسس‌های یک کاربر
ps -ef فرمت دیگر، با ستون PPID
pstree درخت. systemd معمولاً pid برابر ۱ است
pgrep -a nginx pid از روی اسم. -a خط فرمان را هم نشان می‌دهد
top / htop مصرف زنده. در top با q بیا بیرون
jobs کارهای همین شل
bg %1 / fg %1 پس‌زمینه و پیش‌زمینه
cmd & از اول در پس‌زمینه

Ctrl+C سیگنال INT می‌فرستد. Ctrl+Z توقف (STOP) است، مرگ نیست. بعد با fg یا bg برش می‌گردانی.

شماره اسم معنی
1 SIGHUP ترمینال بسته شد؛ بعضی سرویس‌ها با این reload می‌شوند
2 SIGINT Ctrl+C
3 SIGQUIT خروج همراه core dump
9 SIGKILL کشتن اجباری. برنامه فرصت تمیزکاری ندارد
15 SIGTERM درخواست معمولی بستن. پیش‌فرض kill
18 SIGCONT ادامه بعد از توقف
19 SIGSTOP توقف اجباری
20 SIGTSTP Ctrl+Z 
kill 1234            # SIGTERM
kill -9 1234         # SIGKILL
kill -l              # لیست سیگنال‌ها
ping -c 3 1.1.1.1    # سه بسته، بعد تمام
ping -q -c 2 -W 1 example.com

grep یعنی global regular expression print: خط‌هایی را که الگو دارند جدا می‌کند.

ps aux | grep nginx
grep -n "error" /var/log/syslog     # شمارهٔ خط
grep -Rni "TODO" .                  # بازگشتی، شماره، بدون حساسیت به حروف
grep -v "^#" config | grep -v "^$"  # خط‌های کامنت و خالی را حذف کن

systemd

موقع بوت، کرنل systemd را صدا می‌زند. systemd فایل‌سیستم را سوار می‌کند و سرویس‌ها را بالا می‌آورد. هر چیزی که کنترل می‌کند یک unit است: service، socket، timer، mount، target، device. 

systemctl start nginx
systemctl stop nginx
systemctl status nginx
systemctl restart nginx          # می‌کشد و دوباره شروع می‌کند
systemctl reload nginx           # تنظیم تازه، اگر خود سرویس بلد باشد
systemctl reload-or-restart nginx
systemctl enable nginx           # با بوت بیاید بالا
systemctl disable nginx
systemctl is-active nginx
systemctl is-enabled nginx
systemctl list-units
systemctl list-units -t service
systemctl list-unit-files        # حتی unitهایی که لود نشده‌اند
journalctl -u nginx -e           # لاگ همان سرویس، برو آخر فایل
journalctl -xe                   # خطاهای اخیر کل سیستم
journalctl -u nginx --since "1 hour ago"

set -euo pipefail

chmod +x script.sh

متغیرها

فاصله دور = مقدار را خراب می‌کند name = "sara" یعنی دستور name را با دو آرگومان اجرا کن. درستش name="sara" است. 
name="sara"
echo "$name"
echo "${name}_notes"     # اگر بچسبانی به حرف، آکولاد لازم است

read -r city                          # یک خط، بدون تفسیر \
read -r -p "شهر: " city               # پیام می‌دهد و در city ذخیره می‌کند
echo "سلام $city"

# REPLY فقط وقتی پر می‌شود که اسم متغیر ندهی
read -r -p "ادامه؟ "
echo "$REPLY"
read -p ذخیره می‌کند اگر بعد از پیام اسم متغیر باشد، مقدار آنجاست. -r یعنی بک‌اسلش را معمولی بخوان، نه اینکه ورودی خام نباشد.

آرگومان‌های اسکریپت

./script.sh "DevOps notes" extra
# $0 = خود اسکریپت
# $1 = DevOps notes
# $2 = extra
# $# = تعداد آرگومان
# $@ = همه، جدا جدا
# $* = همه، چسبیده با IFS

title="${*:2}"    # از آرگومان دوم تا آخر، یک رشته
rest="${@:2}"     # همان، ولی برای پاس دادن دوباره بهتر است
${*:2} تکهٔ یک رشته نیست این از پارامترهای مکانی است. اگر اسکریپت را این‌طور صدا بزنی: ./script.sh save "my title here" آن‌وقت $1 برابر save است و title="${*:2}" می‌شود my title here. برای بریدن خود یک متغیر بخش رشته‌ها را ببین. 
name="$1"
shift             # $2 می‌آید جای $1، و بقیه یکی جلو می‌آیند
echo "باقی: $#"

آرایه‌ها

آرایهٔ معمولی اندیس عددی دارد. آرایهٔ انجمنی با declare -A کلید رشته‌ای دارد.

hours=()                  # خالی
hours[0]=1
hours[3]=1                # اندیس ۱ و ۲ خالی می‌مانند
echo "${hours[0]}"
echo "${hours[@]}"        # همهٔ مقدارها
echo "${#hours[@]}"       # تعداد خانه‌های پر
echo "${!hours[@]}"       # خود اندیس‌ها: 0 3

hours+=(9)                # به ته اضافه کن
unset 'hours[3]'          # یک خانه را پاک کن، نه کل آرایه

days=(mon tue wed)
for day in "${days[@]}"; do
  echo "$day"
done
ستاره در برابر @ "${hours[@]}" هر خانه یک کلمه است. "${hours[*]}" همه را با فاصله به یک رشته تبدیل می‌کند. داخل حلقه تقریباً همیشه @ را با کوت بخواه. 
# برش آرایه: از اندیس ۱، دو خانه
echo "${days[@]:1:2}"     # tue wed

# نقشه
declare -A weather
weather[tehran]="sunny"
weather[shiraz]="wind"
echo "${weather[tehran]}"
for city in "${!weather[@]}"; do
  echo "$city ${weather[$city]}"
done

شرط و مقایسه

در جزوهٔ اول، علامت‌های مقایسه جابه‌جا نوشته شده بود. داخل [[ ]] برای عدد از این‌ها استفاده کن:

معنی عدد در [[ ]] در (( ))
کوچک‌تر -lt <
کوچک‌تر یا مساوی -le <=
بزرگ‌تر -gt >
بزرگ‌تر یا مساوی -ge >=
مساوی / نامساوی -eq / -ne == / !=

برای رشته داخل [[ ]]: == و !=. علامت < روی رشته ترتیب حروف است، نه اندازهٔ عدد. "10" < "9" در ترتیب حروف درست است و در حساب غلط.

if [[ "$1" == "start" ]]; then
  echo "روشن"
elif [[ -z "$1" ]]; then
  echo "آرگومان نداده‌ای"
else
  echo "ناشناخته"
fi

count=3
if (( count > 0 )); then
  echo "هست"
fi

case "$1" in
  start) systemctl start nginx ;;
  stop)  systemctl stop nginx ;;
  *)     echo "start یا stop" ; exit 1 ;;
esac

head و tail: یک خط مشخص

head -n 10 file          # ده خط اول. پیش‌فرض همین است
tail -n 10 file          # ده خط آخر
tail -n +15 file         # از خط ۱۵ تا آخر
head -n 20 file | tail -n 1    # فقط خط ۲۰
tail -f file             # زنده، برای لاگ
tail -n 50 -f /var/log/syslog

برای یک خط، این‌ها مستقیم‌ترند:

sed -n '20p' file
awk 'NR == 20' file
# بازه
sed -n '15,20p' file
awk 'NR >= 15 && NR <= 20' file

sort -r names.txt            # برعکس
sort -u names.txt            # یکتا. برای خط تکراری
sort -n numbers.txt          # عددی، وگرنه 10 قبل از 2 می‌آید
sort -h sizes.txt            # 1K 2M 3G
sort -t'|' -k2,2 -n data     # جداکننده | و ستون دوم عددی
sort -t',' -k1,1 -k2,2n file # ستون ۱ متنی، ستون ۲ عددی
sort -o out.txt in.txt       # خروجی در فایل

# تکراری‌ها
sort file | uniq
sort file | uniq -c          # با تعداد
sort file | uniq -d          # فقط آن‌هایی که تکرار شده‌اند

sed

جریان متن را خط‌به‌خط عوض می‌کند. s یعنی substitute. جداکننده لزوماً اسلش نیست؛ وقتی با مسیر کار داری # خواناتر است.

sed 's/foo/bar/' file            # اولین foo در هر خط
sed 's/foo/bar/g' file           # همه
sed -n 's/foo/bar/p' file        # فقط خط‌هایی که عوض شدند
sed -n '5p' file                 # خط ۵
sed -n '5,10p' file
sed '5,10d' file                 # این خط‌ها را حذف کن
sed '/^#/d' file                 # خط‌های کامنت
sed '/error/!d' file             # فقط خط‌های error بماند

name=$(printf "%s" "$name" | sed 's/|//g')
name=$(printf "%s" "$name" | sed 's/^"*//; s/"*$//')
name=$(printf "%s" "$name" | sed "s#|$url\$##")

^"*" یعنی ابتدای خط و هر تعداد دابل‌کوت. "*$ یعنی دابل‌کوت‌های انتهای خط. |$url$ یعنی یک پایپ و خود url دقیقاً در انتهای خط.

sed -i روی مک و لینوکس یکی نیست لینوکس: sed -i 's/a/b/g' file. مک: sed -i '' 's/a/b/g' file. برای جزوه، خروجی را در فایل تازه بریز تا غافلگیر نشوی: sed 's/a/b/g' file > file.new

awk

هر خط را به ستون می‌شکند. $1 ستون اول است، $NF ستون آخر، NF تعداد ستون، NR شمارهٔ خط.

awk '{ print $1 }' file
awk -F'|' '{ print $NF }' file          # جداکننده پایپ، ستون آخر
awk -F: '{ print $1, $3 }' /etc/passwd  # اسم و uid
awk -F: '$3 >= 1000 { print $1 }' /etc/passwd
awk 'NR == 5' file
awk 'NR > 1 { print }' file             # بدون هدر
awk '{ sum += $1 } END { print sum }' numbers.txt

در مثال بوکمارک، url ستون آخر است:

url=$(printf "%s" "$line" | awk -F'|' '{ print $NF }')

رجکس عملی

یک خط مثل "نام"|https://example.com را به اسم و آدرس بشکن. جداکننده | است و آدرس آخرین ستون است، چون خود اسم هم ممکن است پایپ داشته باشد.

line='"Linux | notes"|https://example.com/a'

url=$(printf "%s\n" "$line" | awk -F'|' '{ print $NF }')
name=$(printf "%s\n" "$line" | sed "s#|$url\$##")
name=$(printf "%s\n" "$name" | sed 's/|//g')
name=$(printf "%s\n" "$name" | sed 's/^"*//; s/"*$//')
printf "| %s | %s |\n" "$name" "$url" >> unique_bookmarks.md

قدم‌ها: آخر خط را به‌عنوان url بردار، همان url را از ته خط بکن، پایپ‌های باقی‌ماندهٔ داخل اسم را بردار، کوت‌های دور اسم را بردار، یک ردیف مارک‌داون بنویس.

تکه معنی
^ / $ ابتدا / انتهای خط
. هر نویسه
* صفر یا بیشتر از عبارت قبلی
"* صفر یا بیشتر دابل‌کوت
\ نویسهٔ بعدی معمولی است. \$ یعنی خود علامت دلار، نه انتهای خط، وقتی داخل دابل‌کوت بش است
# در sed جداکنندهٔ دستور s، تا لازم نباشد اسلش‌های url را فرار بدهی

همان کار با پارامترهای بش، اگر پایپ فقط یک بار جداکننده باشد:

url="${line##*|}"
name="${line%|$url}"
name="${name//|/}"
name="${name#\"}"
name="${name%\"}"

curl

client URL. صفحه، API، هدر، و آپلود را از ترمینال می‌گیرد. wget بیشتر برای دانلود فایل است.

فلگ کار
-s / -S ساکت / اگر ساکت است باز هم خطا را نشان بده. معمولاً با هم: -sS
-f اگر HTTP خطا بود (۴۰۴، ۵۰۰) خود curl هم شکست بخورد
-L ریدایرکت را دنبال کن
-o file / -O ذخیره با اسم دلخواه / با اسم خود URL
-I فقط هدر، درخواست HEAD
-i هدر به‌علاوهٔ بدنه
-v درخواست و پاسخ، برای دیباگ
-X METHOD GET POST PUT DELETE. با -d خودش POST می‌شود
-H "K: V" هدر
-d 'a=1' بدنه
-u user:pass Basic auth
-k گواهی TLS را چک نکن. فقط برای تست لوکال
-w '%{http_code}' بعد از پاسخ، مثلاً کد وضعیت
-m 10 مهلت به ثانیه 
curl -fsSL -o page.html https://example.com
curl -I https://example.com
curl -sS -H "Accept: application/json" https://api.example.com/items
curl -sS -X POST -H "Content-Type: application/json" \
  -d '{"city":"tehran"}' https://api.example.com/weather
code=$(curl -sS -o /dev/null -w "%{http_code}" https://example.com)
echo "$code"

python3 -m http.server 8080
# اگر index.html همین پوشه باشد، همان باز می‌شود

jq

فیلتر JSON. بدون jq باید با sed روی آکولاد ببُری و می‌شکند.

curl -fsSL https://example.com/data.json | jq .
jq '.name' data.json
jq -r '.name' data.json          # -r رشتهٔ خام، بدون کوت اضافه
jq '.items[0].url' data.json
jq '.items[].name' data.json
jq -r '.[] | "\(.name) \(.url)"' data.json
jq 'map(select(.ok == true))' data.json

name=$(curl -fsSL "$url" | jq -r '.title')
echo "$name"

اگر مقدار null باشد و -e بگذاری، jq با وضعیت غیر صفر خارج می‌شود و زیر set -e اسکریپت می‌ایستد.

eval

eval یک رشته را دوباره به‌عنوان دستور اجرا می‌کند. برای ساختن دستور پویا وسوسه‌کننده است و اگر ذره‌ای از آن رشته از کاربر، فایل، یا اینترنت آمده باشد، همان رشته دستور می‌شود.

# بد: هر چه داخل cmd باشد اجرا می‌شود
cmd="rm -rf /"
# eval "$cmd"

# شکل امن برای دستورهای خودت: آرایه
cmd=(ls -la "/tmp/my notes")
"${cmd[@]}"

# شکل امن برای مقدار
printf -v greeting "سلام %s" "$name"
echo "$greeting"
کی eval قابل دفاع است فقط روی رشته‌ای که خودت ساخته‌ای و هیچ ورودی خارجی داخلش نیست. حتی آن‌وقت هم آرایهٔ دستور معمولاً همان کار را می‌کند. خروجی declare -p را گاهی با eval برمی‌گردانند، چون خودش سینتکس بش است؛ باز هم منبعش باید مطمئن باشد.
جزوهٔ شخصی لینوکس و بش. دستورها را روی ماشین خودت امتحان کن؛ فلگ -i در sed بین گنو و مک فرق دارد.
